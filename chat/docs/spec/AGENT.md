# Памятка для нейронки и нового разработчика

Живой чат «Свои» стоит на домашней приставке `sui`. Репозиторий `tailnet-messenger` описывает тот же стек, но часть путей в шаблоне другая. Перед командой на сервере сверь эту памятку. Продуктовые требования и приёмка лежат в `docs/spec/SPEC.md`.

Секреты в этот файл не входят. Пароли, токен бота, ключи Grafana и `sudo` в git, в чат и в память нейронки не копируют.

Новый процесс на этой машине заводят контейнером Compose проекта `svoi` и сразу оставляют его в том же мониторинге, что и остальные. Отдельный `docker run`, второй compose-проект и сервис без сети `edge` или `data` не добавляют.

## Новый контейнер

Сервис пишут в тот файл, к которому он относится. Чат в `deploy/compose.yml`. Звонки в `deploy/compose.calls.yml`, профиль включается только при `ENABLE_CALLS=true`. Метрики в `deploy/compose.observe.yml`. Образ фиксируют тегом в `.env.example`, не `latest`.

У каждого долгого сервиса один и тот же каркас:

- `restart: unless-stopped`. Одноразовая подготовка, как `synapse-data-init`, стоит `restart: "no"` и больше не повторяется.
- `security_opt: [no-new-privileges:true]`.
- журнал `json-file`, `max-size: 10m`, `max-file: "5"`.
- предел памяти в `deploy.resources.limits.memory`.
- `TZ` из `.env`, если контейнеру нужно местное время.
- секрет файлом из `secrets/`, не строкой в compose и не в git.
- порт на хост только как `127.0.0.1:хост:контейнер`. Исключение одно: медиа LiveKit на IPv4 Tailscale. `0.0.0.0` и порт `8448` не публикуют.
- сеть `edge`, если сервис говорит с другими контейнерами или его проверяет blackbox. Сеть `data` с `internal: true`, если это база или том, которому не нужен выход в интернет. `network_mode: host` не используют.
- `healthcheck`, если у процесса есть локальный адрес здоровья.

Базовый мониторинг после этого уже общий, отдельную панель на контейнер не рисуют.

cAdvisor читает сокет Docker и снимает память, CPU, сеть и перезапуски со всех контейнеров проекта. Grafana на `https://sui.example.com/` показывает их одним списком. Alloy забирает журнал каждого контейнера в Loki через тот же сокет. Поэтому новому сервису хватает каркаса выше: график и логи появляются сами.

Дальше к сервису добавляют одну проверку, если ему есть чем ответить:

- HTTP внутри сети `edge` дописывают в `deploy/observe/prometheus/prometheus.yml`, job `blackbox-apps`. Падение такой проверки само по себе ночью не будит. Ночной будильник остаётся у чата, диска, бэкапа, OOM, подмены адреса Matrix и готовности звонков.
- Свой `/metrics` добавляют отдельным `job_name` на внутренний порт. Цель, которая лежит, график портит, в Telegram ночью не пишут, пока хозяин не попросил отдельный алерт.
- Если от сервиса зависит телефон друга, алерт пишут в `deploy/observe/prometheus/alerts.yml` по-русски, с `summary` и `resolved`, без имён контейнеров.

Prometheus читает этот yaml с диска. После правки `prometheus.yml` или `alerts.yml` контейнер `svoi-prometheus-1` пересоздают. Простой `restart` оставляет старый файл. Остальной стек и LiveKit при этом не трогают.

Проверка перед выкладкой: `docker compose -f deploy/compose.yml -f deploy/compose.calls.yml -f deploy/compose.observe.yml config` и `make ci`. В списке сервисов новый контейнер есть, порт наружу не светится, в Prometheus есть либо цель blackbox, либо объяснение, почему сервису нечего опрашивать.

## Два места

Код и шаблоны: приватный репозиторий `N4L34/tailnet-messenger`. Заметки хозяина без секретов: приватный `N4L34/svoi`.

На приставке каталог `/home/sui/tailnet-messenger`, пользователь Linux `sui`. Юнит systemd, который реально крутится, тоже смотрит в этот каталог. Файл `deploy/systemd/svoi.service` в git всё ещё пишет `WorkingDirectory=/opt/tailnet-messenger`. Его не копируют поверх `/etc/systemd/system/svoi.service`. Живой таймер бэкапа тоже свой. Шаблонный юнит с `/opt` его не заменяет.

Рабочая копия на Маке хозяина может обгонять и git, и сервер. Выкладка на `sui` сама не происходит от `git push`. CI ничего на сервер не ставит.

## Кто здесь кто

Хозяин: Оператор Латышев, GitHub `N4L34`. Новый разработчик получает доступ к приватным репозиториям. SSH на приставку и админку Matrix ему не выдают, пока хозяин не скажет отдельно.

Друзья ходят в Element через Tailscale. Учётные записи создаёт хозяин или бот в личке Telegram. Открытой регистрации нет.

Сейчас в Matrix есть `@operator` (админ сервера, имя на сервере `operator`), `@sergon` (Сергон, комната «Друзья»), `@elina` (в «Друзья» не входит), `@serzh` (Серж, это другой человек, не Сергон), `@ping` (проверочный, не друг), `@svoibot` (служебный админ бота, имя «Свои»). Пароли здесь не записаны. `@operator` и `@svoibot` не удаляют и не сбрасывают. Комнату «Друзья» и безымянные комнаты не чистят ради проверки.

## Запреты на живом сервере

`systemctl restart svoi.service` и `systemctl stop svoi.service` гасят стек: `ExecStop` вызывает `make down`. Чтобы подхватить один контейнер, перезапускают его через `docker compose` из `/home/sui/tailnet-messenger`, с тем же набором файлов, что у `make`. Флаг `--remove-orphans` не ставят.

Пересоздание контейнера `svoi-livekit-1` рвёт текущий звонок. LiveKit оставляют на `livekit/livekit-server:v1.13.10`. Образ `v1.9.0` маршрут `/rtc/v1` не умел, из-за этого звонок обрывался примерно через 15 секунд. На `v1.13.10` голый `/rtc/v1` отвечает 404, а `/rtc/v1/validate` без токена отвечает 401. 404 на голом `/rtc/v1` для этой версии норма.

`use_ice_lite: true` уже стоял во время тех обрывов. Его не снимают и не объявляют причиной починки.

Полный `scripts/render_config.py` на приставке переписывает homeserver, Element, LiveKit и Caddy. На живой машине так не делают. Меняют нужный кусок сгенерированного файла и перезапускают только тот контейнер, который его читает. `rsync` поверх файла, который уже примонтирован в контейнер, оставляет процесс на старом inode. Такой контейнер пересоздают точечно, LiveKit при активном звонке не трогают.

Наружу не публикуют `8448`, не включают слушатель `names: [federation]`, не ставят `SkipVerifyTLS`, не вешают медиа на `0.0.0.0` и не направляют `use_external_ip` в публичный адрес. Файрвол хоста с политикой DROP этот репозиторий не включает. Docker `userland-proxy` не выключают и `dockerd` не перезапускают.

Машину не перезагружают без просьбы хозяина. Новых пользователей Linux не заводят. Пароль `sudo` не угадывают и не пишут в ответ. `sudo -n` на `sui` без пароля не работает.

Экран приставки гасит `sui-dark-mode`. Подсветку включают только по просьбе хозяина.

## Как зайти

Имя в Tailscale: `sui.example.com`. IPv4 в tailnet: `100.64.0.10`. В локальной сети приставки: `192.0.2.15` на `wlp2s0`.

С Мака хозяина обычный маршрут до `100.64.0.10` часто уходит в домашний роутер, а не в интерфейс Tailscale. Тогда `ssh sui` и `ssh 100.64.0.10` зависают или не резолвятся. Номер `utun` меняется. Берут тот, на котором висит адрес Мака из сети `100.64.0.0/10`.

```bash
IFACE=$(ifconfig | awk '/^utun/{i=$1} /inet 100\./{gsub(":","",i); print i; exit}')
ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes -o BindInterface="$IFACE" \
  -o HostKeyAlias=192.0.2.15 -o BatchMode=yes sui@100.64.0.10
```

`HostKeyAlias` нужен потому, что ключ хоста записан для старого адреса `192.0.2.15`. Короткое имя `sui` без записи в `~/.ssh/config` система может не найти. Полное имя `sui.example.com` MagicDNS отдаёт, когда Tailscale DNS на Маке включён.

Если интерфейс связать нельзя, канал открывает само приложение Tailscale:

```bash
ssh -o 'ProxyCommand=/Applications/Tailscale.app/Contents/MacOS/Tailscale nc %h %p' \
  sui@100.64.0.10
```

Пока Tailscale на Маке остановлен или приставка не в tailnet, SSH не заработает. Обычный интернет этого не заменяет. В `tailscale status` смотрят, что узел `sui` online.

## Имя сервера

`MATRIX_SERVER_NAME` на этой машине навсегда `sui.example.com`. Оно уже в адресах `@user:sui.example.com`. Другое имя в рендер не подставляют. Пример `messenger.example.com` в шаблоне к этой приставке не относится.

Часы хоста в UTC. Контейнеры в `Europe/Moscow`. У systemd на этой машине `Timezone=` в таймере не срабатывает, поэтому календари записаны в UTC.

## Что слушает

Дверь с телефонов одна: Tailscale Serve. Публичного порта у чата нет.

```text
:443 /             -> 127.0.0.1:3000   Grafana
:443 /_matrix      -> 127.0.0.1:8008   Synapse, префикс возвращают
:443 /_synapse     -> 127.0.0.1:8008   Synapse
:443 /.well-known  -> 127.0.0.1:8008   Synapse
:8443              -> 127.0.0.1:8080   Element Web
:8444              -> 127.0.0.1:7882   звонки
```

Порт `:3443` выключен. Если `https://sui.example.com/_matrix/client/versions` отдаёт не JSON Matrix, Serve вернули не туда и это чинят сразу.

Synapse `v1.163.0` публикует `127.0.0.1:8008`. Postgres 17 сидит во внутренней сети `data` и наружу не ходит. Element Web `v1.12.32`. Проект Compose называется `svoi`. Тома `svoi_synapse-data` и `svoi_postgres-data` не удаляют: в первом ключ подписи.

На 28 октября 2026 в живом `homeserver.yaml` есть `enable_registration: false`, пустой `federation_domain_whitelist`, `use_presence: false` и более мягкий `rc_login` (burst 10 у адреса и учётки, burst 8 у неудачных попыток, дальше прежний темп). Слушателя федерации нет. `rc_presence` на сервере ещё старый. Флаги `msc4502` и `msc4512` на сервере не включены.

Grafana открывается с корня `https://sui.example.com/`. Логин `admin`. Пароль лежит в `secrets/grafana_admin_password` на приставке и в ответы не попадает.

## Звонки

`ENABLE_CALLS=true`. Рядом с Synapse работают LiveKit `v1.13.10`, `lk-jwt` (образ `latest`, отдельным контейнером, не как приложение Synapse), Caddy `calls-proxy` и `call-dial`.

`use_external_ip: false`, `node_ip: 100.64.0.10`, `room.auto_create: false`, `use_ice_lite: true`. Сигналинг `7880` только на `127.0.0.1`. Медиа `7881` и UDP `50000-50100` висят на `100.64.0.10`.

Клиент Element X при обрыве связи стучится в `POST /_matrix/client/unstable/io.element.msc4195/rtc/livekit/delegate_delayed_leave`. Живой Synapse отвечает 404: сервис токенов к нему как приложение не подключён. В рабочей копии репозитория это уже размечено (`msc4502`, `msc4512`, файл регистрации, монтирование в `deploy/compose.calls.yml`). На приставку это не выкладывали. Пока выкладка не сделана, обрыв телефона сервер сам не закрывает.

Проверка «звонки живы» для алерта: `/rtc/v1/validate` без токена даёт 401, и порты медиа принадлежат адресу Tailscale. В рабочей копии удачный 401 запоминается на 10 минут, чтобы LiveKit не писал предупреждение каждую минуту. На сервере этой паузы ещё нет, проверка ходит раз в минуту.

## Telegram

Алерты и сводки шлёт `scripts/telegram_notify.py`. Людей и комнаты ведёт `scripts/telegram_bot.py` в службе `svoi-telegram-bot.service` от пользователя `sui`. Эта служба отдельно от `svoi.service`. Чтобы подхватить новый бот, перезапускают только её.

С приставки до `api.telegram.org` по имени достучаться нельзя. Скрипты и Alertmanager ходят на закреплённый адрес `149.154.167.220`, имя в TLS остаётся `api.telegram.org`. Переменная `TELEGRAM_API_IP`.

Команды бот принимает в личке `@ExampleBot` и только от админов канала алертов. Пароль уходит только в эту личку. В канал `SuiAlerts` пароли не пишут. Повторный пинг в канал без просьбы не шлют.

Команды: `новый Ник`, `создай Ник логин latin`, `сбрось логин`, `удали логин`, `удали совсем логин`, `группы`, `группа`, `назови`, `тема`, `пригласи`, `выгони`. В Element вставляют короткий логин с отдельной строки, без `@` и без пробела в конце. Пробел в конце полного адреса Synapse считает другим пользователем. Новый пароль состоит из четырёх групп по четыре знака через дефис, без похожих `0/O` и `1/l`.

`@svoibot` заходит в комнату только на время правки и потом выходит. Создателем комнаты, которую потом надо править, его не делают: в комнате версии 12 создатель не может снова войти через `make_room_admin`.

## Наблюдаемость

Профиль observe включён. Ночной алерт в Telegram: homeserver недоступен, диск ниже 15%, локальный бэкап старше 26 часов, внешний бэкап старше 26 часов, OOM, по корню Tailscale Serve вместо Matrix открылась Grafana, звонки не готовы, пропала проверка края. Повтор раз в 4 часа.

Обычный обрыв звонка, счётчик комнат LiveKit, ошибка пуша, строка Loki и короткий всплеск CPU в ночной канал не идут. Падение метрик Synapse при живом API попадает в утреннюю сводку.

Утро: `05:00` UTC, это `08:00` по Москве. Неделя: воскресенье `08:00` UTC, это `11:00` по Москве. Текст для друзей, без имён контейнеров.

Бэкап по таймеру `svoi-backup.timer`. Каталог `backups/` на сервере в git не кладут.

## Секреты и git

В коммит не попадают `.env`, `secrets/`, `deploy/rendered/`, `deploy/observe/alertmanager/bot_token`, дампы и архивы. Пример настроек лежит в `.env.example`. Пример с Мака на приставку как боевой конфиг не копируют.

На приставке пароли сервисов лежат в `secrets/` с режимом `600`. Токен Telegram для Alertmanager ещё раз скопирован в `deploy/observe/alertmanager/bot_token` с режимом `644`, потому что Alertmanager работает как `nobody`. В yaml токена нет, там только номер чата.

`gitleaks` в CI ловит ключи. Если секрет уже попал в переписку, его не вставляют в файл и не повторяют в ответе.

## Как менять код

Правку делают в репозитории и гоняют `make ci`. На приставку уезжают только названные файлы, через `rsync` по SSH с интерфейсом Tailscale. После выкладки проверяют конкретную службу.

Безопасные локальные проверки: `python3 scripts/telegram_bot.py --self-test` и `make ci`. `telegram_bot.py --check` на живом сервере заводит временного пользователя и комнату, потом убирает их. Его запускают, только если хозяин просил проверить бота.

Synapse после правки `homeserver.yaml` перезапускают контейнером `svoi-synapse-1`. Клиенты на минуту отвалятся и подключатся сами. LiveKit при этом не перезапускают.

Коммитит и пушит хозяин, либо разработчик после явной просьбы. В сообщение коммита секреты не входят.
