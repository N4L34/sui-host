# Модель угроз

Речь о чате на 2–15 человек за Tailscale. Это не модель публичного homeserver и не обещание спрятать факт переписки от хозяина сервера.

## Что защищаем

- Текст, файлы и голосовые сообщения в зашифрованных комнатах от постороннего в интернете и от других пользователей tailnet, которые не состоят в комнате.
- Пароли, `registration_shared_secret`, macaroon, form secret, ключ подписи, пароль restic.
- Возможность завести аккаунт на этом чате.

Шифрование комнат включено по умолчанию. Ключи устройств хранят клиенты. Сервер пересылает шифротекст и не получает общий секрет комнаты, пока кто-то сам не подтвердил чужую сессию.

## Кто есть кто

- Хозяин сервера. Администратор Matrix, владелец tailnet, root на хосте. Ему доступны диск, дамп и метаданные.
- Участник. Учётная запись в чате и устройство в tailnet. Видит комнаты, куда его пригласили, и порты из ACL.
- Человек в том же tailnet без учётки Matrix. Может открыть TCP 443 и 8443, если ACL его пускает. Зарегистрироваться не может.
- Посторонний в интернете. Публичного слушателя чата нет. Остаются провайдер VPS, координация Tailscale и шлюз пушей.
- Шлюз Element на matrix.org. Получает идентификатор события и push-токен. Тело сообщения ему не отправляют.
- Координация Tailscale. Видит устройства, ключи WireGuard и факт соединений. Переписку Matrix не видит.

## Границы

1. Телефон говорит только с tailnet. Дальше `tailscale serve` попадает на loopback.
2. Postgres доступен только из внутренней сети Docker `data`. В неё входят Synapse и postgres-exporter. Element и Grafana в эту сеть не входят.
3. Секреты лежат в `secrets/`, `.env` и `deploy/rendered/`. В git их нет. `make ci` гоняет gitleaks по истории репозитория.
4. ACL чата: участник не открывает SSH. Grafana слушает тот же `tcp/443`, что и чат, отдельного `tcp/3443` нет, дальше пускает пароль администратора. Политику остальных машин tailnet этот файл не заменяет.
5. Стек не ставит правила файрвола хоста. Чужие сервисы VPS остаются как были. Медиа звонков публикуется только на адресе Tailscale.

## Что остаётся видимым

Хозяин сервера и любой, кто прочитал базу, видит метаданные: список пользователей, членство в комнатах, время событий, имена комнат, IP внутри tailnet на момент запроса, размеры файлов. Выключенный presence уменьшает поток статусов, но не делает факт сообщения невидимым для сервера.

Каталог `backups/` лежит на диске этого же хоста. Забирайте его вместе с остальными копиями сервера.

Потерянный телефон: сессию гасят в Element, пароль меняет хозяин через admin API (`logout_devices`). Ключ восстановления, если он был только на этом телефоне, не восстановит историю. Инструкция: `docs/runbooks/lost-device.md`.

## Особые компоненты

Alloy в профиле наблюдаемости читает `/var/run/docker.sock`. Это права демона Docker, то есть фактически root на хосте. Профиль выключен, пока не выполнен `make observe`. Включают его только на своём хосте.

cAdvisor в этом профиле запускается привилегированным. Это нужно сборщику метрик контейнеров. Рядом с чатом посторонних контейнеров быть не должно.

LiveKit при звонках публикует UDP только на IPv4 Tailscale. Публичный адрес VPS для этого не используется.

Состояние Terraform хранит auth key, потому что cloud-init подставляет его в user-data. Файл `*.tfstate` в gitignore. Не кладите его в тикет и в публичный gist.

## Чего модель не покрывает

Злой хозяин сервера. Он может подменить клиент на Element Web, прочитать метаданные и сохранить дамп. От этого защищает проверка эмодзи и клиент из магазина, не конфиг Synapse.

Компрометация аккаунта Tailscale хозяина. Тогда злоумышленник видит узлы и, если он админ ACL, открывает SSH. Ключи Tailscale и пароль админки Tailscale хранят отдельно от дампа Matrix.

Уязвимость в Synapse, Element или ядре. Этот репозиторий их не патчит. Обновление — смена закреплённого тега после бэкапа.
