# Обновление

## Симптомы

Вы хотите сменить тег образа в `.env`. Обычно это `SYNAPSE_IMAGE`. Реже вместе с ним меняют `ELEMENT_WEB_IMAGE` или другой тег из того же файла. Чат сейчас работает, и вы не хотите потерять базу.

## Вероятные причины

Поломка после обновления почти всегда из двух источников. Новый образ Synapse не стартует на текущем конфиге, либо он уже мигрировал базу, и прежний тег на ней не запускается. Откат тега без заранее снятой копии тогда не спасает.

## Проверки

Прочитайте список изменений той версии, которую собираетесь вписать. Для Synapse это страница релизов проекта: https://github.com/element-hq/synapse/releases

Посмотрите текущий тег и что сервер жив:

```bash
grep '^SYNAPSE_IMAGE=' .env
make smoke
```

Запомните строку тега. Она понадобится, если придётся вернуть её назад.

## Исправление

Не пропускайте копию, даже если обновление кажется маленьким.

1. Снимите копию и дождитесь окончания:

```bash
make backup
```

В `backups/` должен появиться новый каталог. Запомните его имя.

2. Измените тег образа в `.env`. Другие настройки не меняйте тем же шагом.
3. Соберите конфиг и поднимите стек:

```bash
make render
make up
make smoke
```

У сервиса Synapse `stop_grace_period` равен 60 секундам. Пока `make up` пересоздаёт контейнер, Docker ждёт до минуты, чтобы Synapse записал состояние и вышел. Не останавливайте контейнер через `docker kill` в эту минуту.

Том Postgres при `make up` остаётся. `make down` тоже не удаляет тома. Обновление не должно создавать пустую базу.

Не меняйте мажорную версию Postgres тем же шагом, что и Synapse. Существующий том от этого сам не переезжает на новую мажорную версию.

4. Если `make smoke` не прошёл, верните в `.env` предыдущий тег и запустите стек снова:

```bash
make up
make smoke
```

Если старый образ отказывается стартовать, потому что новая версия уже изменила схему базы, не повторяйте запуск. Восстановите снимок, снятый перед обновлением:

```bash
make restore CONFIRM=yes SNAPSHOT=backups/20261019T120000Z
```

Подставьте каталог из шага 1. Дальше идите по `docs/runbooks/restore.md`.

## Как убедиться

`make smoke` печатает `smoke passed`. Обе проверки отвечают:

```bash
curl -fsS http://127.0.0.1:8008/health
curl -fsS http://127.0.0.1:8008/_matrix/client/versions
```

`docker compose -f deploy/compose.yml --env-file .env ps` показывает запущенные `synapse` и `postgres` без перезапуска. Отправьте сообщение от operator к alice. Друзья ничего заново не настраивают, если smoke прошёл на новом теге.
