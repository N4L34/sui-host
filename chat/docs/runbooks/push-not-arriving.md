# Уведомление на iPhone не приходит

Различайте два случая. Они чинятся по-разному.

- Баннера нет вообще. Телефон не получил сигнал пробуждения.
- Баннер есть, а текста сообщения нет. Сигнал дошёл, но Element X не забрал текст с сервера.

Сигнал пробуждения идёт через шлюз Element на matrix.org. Текста сообщения в нём нет. Текст приложение забирает само с homeserver. Homeserver доступен только через Tailscale.

## Симптомы

Сообщение есть в чате на другом устройстве. На заблокированном iPhone либо нет баннера, либо баннер пустой и без текста. Сам чат при открытом приложении и подключённом Tailscale может при этом работать.

## Вероятные причины

Нет баннера:

- В iOS запрещены уведомления Element X.
- Человек вошёл в аккаунт, но Element X не зарегистрировал pusher.
- Сервер не открывает исходящий HTTPS к matrix.org, поэтому Synapse не доносит сигнал до шлюза Element.
- Часы сервера сильно разошлись с реальным временем, и HTTPS из-за этого обрывается.

Баннер без текста:

- На телефоне выключен Tailscale.
- VPN On Demand стоит не Always для Wi-Fi или не Always для Cellular.
- Домашняя сеть Wi-Fi исключена из VPN On Demand. Имя сервера и дома находится только через Tailscale.
- Часы разъехались так, что пробуждение дошло, а запрос к серверу нет.

Android здесь редкий случай. Пробуждение ему несёт FCM. Текст всё равно загружается только при подключённом Tailscale.

## Проверки

На iPhone откройте Tailscale и посмотрите, что VPN подключён. В VPN On Demand должно быть Always и для Wi-Fi, и для Cellular. В списке исключений не должно быть домашней сети.

В iOS откройте Settings → Notifications → Element X и проверьте, что уведомления разрешены. В Element X откройте настройки уведомлений и проверьте, что они включены.

На сервере:

```bash
date -u
curl -fsS -o /dev/null -w '%{http_code}\n' --max-time 15 https://matrix.org/
docker compose -f deploy/compose.yml --env-file .env logs --tail=200 synapse
tailscale status
```

`curl` должен напечатать код `200`. Другой код или таймаут значит, что исходящий HTTPS к matrix.org не работает. В логе Synapse ищите ошибки отправки push.

Проверьте, есть ли pusher у alice. Подставьте текущий пароль администратора. Запрос идёт только на `127.0.0.1`.

```bash
TOKEN=$(curl -fsS -X POST http://127.0.0.1:8008/_matrix/client/v3/login \
  -H 'content-type: application/json' \
  -d '{"type":"m.login.password","identifier":{"type":"m.id.user","user":"operator"},"password":"ТЕКУЩИЙ_ПАРОЛЬ"}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')

curl -fsS -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8008/_synapse/admin/v1/users/%40alice%3Amessenger.example.com/pushers"
```

Пустой список `pushers` значит, что приложение не зарегистрировало pusher. Не сохраняйте токен и не отправляйте его в чат.

## Исправление

1. Если баннера нет и `curl` к `https://matrix.org/` не даёт `200`, серверу нужен исходящий HTTPS. Входящий порт для пуша не нужен.
2. Если `date -u` отстаёт или спешит больше чем на пару минут, включите синхронизацию времени. На Ubuntu выполните `timedatectl set-ntp true` и снова проверьте `date -u`.
3. Если уведомления iOS выключены, включите их для Element X. Если список pushers пуст, в Element X включите уведомления. Если запись не появляется, выйдите из аккаунта в Element X и войдите снова тем же пользователем. Новый аккаунт не создавайте.
4. Если баннер без текста, на телефоне включите Tailscale. В VPN On Demand поставьте Always для Wi-Fi и Always для Cellular. Уберите домашнюю сеть из исключений. Имя `messenger.example.com` должно открываться только так.

## Как убедиться

Оставьте iPhone заблокированным, с выключенным экраном и подключённым Tailscale. С Mac или другого телефона отправьте alice сообщение от operator. На iPhone должен появиться баннер с текстом этого сообщения, а не пустое пробуждение.

Повторите проверку дважды: на сотовой сети с выключенным Wi-Fi и дома на Wi-Fi. Оба раза текст должен быть в баннере. Повторный запрос pushers должен показать хотя бы одну запись.
