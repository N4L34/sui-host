# Tailscale не соединяет друзей с сервером

## Симптомы

Друзья не открывают «Свои». Имя `messenger.example.com` не находится. `tailscale status` показывает узел офлайн, просит войти снова или не может связаться с координацией. Чат с телефона не открывается, хотя домашний сервер на машине ещё жив.

Публичного запасного входа нет. Это сделано специально. Не открывайте 443, 8443 или 8448 на публичном адресе, чтобы «переждать» поломку.

## Вероятные причины

Разделяйте три поломки.

- Координация Tailscale недоступна. Компания Tailscale не отвечает, и узлы этого tailnet не могут узнать друг друга. Люди на Headscale в этот момент не страдают: у них другой координационный сервер. Люди на обычном Tailscale до сервера не доходят.
- На сервере или на телефоне остановлен местный `tailscaled` либо приложение Tailscale.
- Истекла авторизация узла. Ключ был одноразовым и уже использован, узел вышел из tailnet, или его нужно заново одобрить.

DERP по-прежнему переносит трафик, когда прямой UDP между узлами закрыт. Это релей уже установленной сети, а не второй вход и не замена координации. Если не работает координация, новые соединения и MagicDNS не поднимаются. Ждать, что DERP сам откроет чат, не нужно.

## Проверки

На сервере:

```bash
tailscale status
tailscale serve status
curl -fsS http://127.0.0.1:8008/health
```

На Ubuntu дополнительно:

```bash
systemctl status tailscaled
```

На Mac смотрите приложение Tailscale в строке меню, а не systemd.

На телефоне откройте Tailscale и проверьте, что состояние Connected. С телефона имя `messenger.example.com` должно открываться только при включённом Tailscale.

Если `curl` к `127.0.0.1:8008` не проходит, сначала чините сервер по `docs/runbooks/homeserver-down.md`. Эта страница про путь до уже живого сервера.

## Исправление

1. Если `tailscaled` на Ubuntu остановлен, запустите его и проверьте узел:

```bash
systemctl restart tailscaled
tailscale status
```

На Mac закройте приложение Tailscale и откройте его снова из строки меню. Дождитесь Connected.

2. Если узел вышел из tailnet и `tailscale status` просит войти, выпустите в консоли Tailscale новый одноразовый auth key с тегом `tag:messenger`. Старый одноразовый ключ повторно не используйте. На сервере выполните:

```bash
tailscale up \
  --auth-key="НОВЫЙ_КЛЮЧ" \
  --advertise-tags=tag:messenger \
  --ssh \
  --hostname=messenger \
  --accept-dns=true
make serve
tailscale serve status
```

3. Если на телефоне Tailscale выключен или VPN On Demand исключил текущую сеть, включите его. Always для Wi-Fi и Always для Cellular, без исключения домашней сети. Это та же настройка, что в `docs/guides/iphone.md`.
4. Если не отвечает сама координация Tailscale, подождите. Узлы этого tailnet дождутся, пока `tailscale status` снова покажет сервер. Homeserver в публичный DNS не публикуйте.

Пока tailnet не работает, друзья до сервера не доходят. Текстовый чат не переключается на открытый адрес.

## Как убедиться

На сервере `tailscale status` показывает узел и телефоны друзей. `tailscale serve status` показывает HTTPS для `443` и `8443`. Местный сервер отвечает:

```bash
curl -fsS http://127.0.0.1:8008/health
make smoke
```

С телефона на сотовой сети, с выключенным Wi-Fi, откройте Element X и отправьте сообщение от alice к operator. Сообщение должно дойти без какого-либо публичного адреса сервера.
