# Потерян телефон друга

## Симптомы

У alice пропал iPhone, на котором был вход в «Свои». Телефон мог остаться разблокированным, поэтому чужой человек может читать комнаты, пока сессия жива.

## Вероятные причины

Сессия устройства всё ещё действительна. Пароль на потерянном телефоне тоже ещё действует, если его не сменили. Старая переписка зашифрована. Её можно прочитать на новом телефоне только ключом восстановления из Element X → Settings → Encryption → Recovery.

## Проверки

Спросите alice две вещи. Есть ли Element ещё на одном устройстве, например на Mac. Записан ли ключ восстановления не в потерянном телефоне.

Посмотрите устройства на сервере. Подставьте текущий пароль operator. Запрос остаётся на `127.0.0.1`:

```bash
TOKEN=$(curl -fsS -X POST http://127.0.0.1:8008/_matrix/client/v3/login \
  -H 'content-type: application/json' \
  -d '{"type":"m.login.password","identifier":{"type":"m.id.user","user":"operator"},"password":"ТЕКУЩИЙ_ПАРОЛЬ"}' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')

curl -fsS -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8008/_synapse/admin/v2/users/%40alice%3Amessenger.example.com/devices"
```

В ответе найдите `device_id` потерянного iPhone. Ориентир — `display_name` и время `last_seen_ts`. Токен никуда не пересылайте.

## Исправление

1. Закройте потерянную сессию. Если у alice есть другой вход в Element, откройте там список сессий и выйдите из сессии потерянного iPhone.
2. Если другого входа нет, удалите это устройство через admin API Synapse. Подставьте `device_id` из проверки:

```bash
curl -fsS -X DELETE -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8008/_synapse/admin/v2/users/%40alice%3Amessenger.example.com/devices/DEVICE_ID"
```

3. Смените пароль alice, чтобы потерянный телефон не вошёл заново. Команда также выходит из всех устройств этого пользователя, включая Mac, если он ещё был в аккаунте. На нём потом входят заново:

```bash
python3 scripts/matrix_admin.py reset \
  --admin operator \
  --password 'ТЕКУЩИЙ_ПАРОЛЬ_АДМИНА' \
  --user alice \
  --new-password 'НОВЫЙ_ОДНОРАЗОВЫЙ_ПАРОЛЬ'
```

Новый пароль скажите лично или каналом, который не является этим чатом. Новый аккаунт не создавайте. Имя остаётся `@alice:messenger.example.com`.

4. На новом iPhone alice проходит `docs/guides/iphone.md`: Tailscale, Element X, новый пароль, снова хранилище ключей.
5. Новое устройство нужно проверить сравнением эмодзи с оператором или с другой своей уже проверенной сессией.
6. Ключ восстановления возвращает старую зашифрованную историю. Если ключа восстановления нет, старая зашифрованная история на сервере нечитаема. Сервер хранит шифротекст, но расшифровать его нечем. Новые сообщения после входа и проверки устройства читать можно.

## Как убедиться

Повторите запрос списка устройств. `device_id` потерянного iPhone в нём отсутствует. Вход со старым паролем не проходит.

С нового телефона alice отправляет сообщение operator, и оно приходит. Старые сообщения видны только если alice ввела прежний ключ восстановления. Если ключа не было, не обещайте вернуть старую переписку.
