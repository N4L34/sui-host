# Диск заполнен

## Симптомы

`df -h` показывает, что на корневом диске не осталось места. Postgres не пишет данные. Загрузка файлов в чат падает. Контейнеры завершаются или перезапускаются. `make smoke` не проходит.

## Вероятные причины

- Медиа в томе Synapse растёт вместе с фото и голосовыми сообщениями.
- Местные снимки в `backups/` тоже содержат полную копию медиа. Скрипт хранит 14 каталогов на том же диске.
- Образы Docker копятся после обновлений.
- Журналы контейнеров здесь маловероятная причина. В compose для них задан предел 10 МБ на файл и 5 файлов на сервис.

## Проверки

```bash
df -h
docker system df
docker compose -f deploy/compose.yml --env-file .env ps
du -sh backups
docker run --rm -v svoi_synapse-data:/data:ro alpine:3.22 du -sh /data /data/media_store
```

Последняя команда показывает размер ключа, медиа и всего тома Synapse. Сам том она не меняет.

## Исправление

Не запускайте `docker volume prune`, `docker system prune --volumes` и `docker compose down -v`. Эти команды удаляют базу и ключ подписи.

1. Уберите неиспользуемые образы, если `docker system df` показывает, что их можно вернуть:

```bash
docker image prune
```

Подтверждайте только то, что Docker считает неиспользуемым. Тома не трогайте.

2. Разберите `backups/`. Каждый каталог — полная копия медиа. Удаляйте старый каталог только если эта копия уже лежит вместе с остальными бэкапами сервера. Последний каталог оставьте и проверьте его командой `make drill`.
3. Медиа лежит в томе и нужно чату. Не чистите `/data/media_store` руками и не удаляйте том. Если места всё равно нет, расширьте диск у того провайдера, где стоит машина.
4. После увеличения диска выполните `lsblk` и `df -h`. Если диск стал больше, а корневой раздел нет, расширьте раздел и файловую систему так, как принято на этой системе. Номер раздела берите из `lsblk`. Снова выполните `df -h`.
5. На Mac освободите место на диске самой машины. Затем увеличьте предел диска Docker Desktop в Settings → Resources или предел диска OrbStack. Перезапустите Docker и снова проверьте `df -h` внутри среды, где лежат тома.

## Как убедиться

`df -h` показывает свободное место с запасом, а не нули. Затем:

```bash
docker compose -f deploy/compose.yml --env-file .env ps
make smoke
```

Отправьте в комнату «Друзья» небольшое фото. Сообщение должно дойти. `docker system df` не должен показывать, что тома исчезли.
