# Восстановление из снимка

## Симптомы

Чат потерял данные, обновление испортило базу, или вы поднимаете сервер заново на том же имени. Есть каталог снимка в `backups/` или копия этого каталога из restic.

## Вероятные причины

- Диск или том Docker повреждены.
- Обновление Synapse уже мигрировало базу, а старый образ на ней не стартует.
- Кто-то восстановил только часть данных и получил сервер, которому клиенты больше не доверяют.

## Проверки

Найдите снимок. Имя каталога выглядит как `backups/20261019T120000Z`.

```bash
ls backups
```

В выбранном каталоге должны лежать три файла: `postgres.dump`, `synapse-data.tar` и `secrets.tar`. Не начинайте, если любого из них нет.

```bash
ls backups/20261019T120000Z
```

Подставьте свой штамп. `make drill` проверяет только дамп Postgres и живую базу не трогает. Перед боевым восстановлением его можно выполнить на копии, которая ещё не является единственной.

## Исправление

Восстановление заменяет живой сервер целиком. Сообщения, появившиеся после этого снимка, пропадут. Другую копию команды не собирайте и отдельную команду Synapse для этого не запускайте. Путь в репозитории один:

```bash
make restore CONFIRM=yes SNAPSHOT=backups/20261019T120000Z
```

Без `CONFIRM=yes` скрипт отказывается работать. Он сам останавливает стек, возвращает секреты и сгенерированный конфиг из `secrets.tar`, распаковывает том `svoi_synapse-data` из `synapse-data.tar`, заново создаёт базу и загружает её через `pg_restore`, затем запускает стек.

Не восстанавливайте только `postgres.dump`. Ключ подписи лежит в `synapse-data.tar`, в файле `/data/signing.key` тома Synapse, а не в дампе базы. Федерация выключена, но ключ всё равно подписывает события и ключи устройств. Потеря ключа отменяет эти подписи сервера. Клиенты, которые уже запомнили ключ, могут показать предупреждение. Новый пустой том плюс старая база — это как раз такая поломка. `make restore` берёт ключ, секреты и базу из одного снимка. Так и оставляйте.

Сессии переживают восстановление, если секрет macaroon в этом снимке совпадает с базой. Смешивать `secrets.tar` одного снимка с базой другого нельзя.

## Как убедиться

Скрипт в конце просит проверить сервер. Выполните:

```bash
make smoke
curl -fsS http://127.0.0.1:8008/health
curl -fsS http://127.0.0.1:8008/_matrix/client/versions
```

`make smoke` должен напечатать `smoke passed`. Напишите друзьям другим каналом, что сообщения на время сбоя нужно отправить ещё раз. Отправьте пробное сообщение от operator к alice.

Если клиент предупреждает, что личность сервера изменилась, снимок собран не целиком: база есть, а прежний ключ подписи нет. Остановитесь и восстановите каталог, в котором есть и `postgres.dump`, и `synapse-data.tar`. Не создавайте новый ключ поверх старой базы.
