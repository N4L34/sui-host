# SLO

Один узел, без дежурной смены и без второй площадки. Цифры ниже — договор с самим собой, не тариф для посторонних.

Окно — календарный месяц.

## Цели

| Что | Цель | Как смотрим |
| --- | --- | --- |
| Доступность клиентского API | 99.5% | blackbox на `/health` и `/_matrix/client/versions` из профиля наблюдаемости. Без профиля — `make smoke` руками. |
| Отправка сообщения внутри tailnet | p95 быстрее 500 мс | Время на уже поднятом туннеле. Поднятие VPN в замер не входит. |
| Восстановление | RPO 1 час, RTO 60 минут | Почасовой бэкап. Учебный прогон `make drill`. Боевой `make restore` укладывают в час на этом размере базы. |

99.5% — это около 3,6 часа недоступности в месяц. Туда входят перезагрузка VPS, `make up` при обновлении и сон хоста, если хостом ошибочно сделали ноутбук.

## Что в цель не входит

- Доставка пуша. Её держат Apple, Google, шлюз Element и VPN на телефоне.
- Звонки. Профиль выключен по умолчанию и считается best-effort.
- Федерация. Её нет.
- Время, пока Tailscale на телефоне не подключён. Для телефона это «нет сети», не простой сервера.

## Бюджет ошибок

При 99.5% бюджет месяца — 3 часа 39 минут. Потратили его на плановое обновление — в этом месяце второе обновление переносят, если нет дыры.

Считать просто, когда включён `make observe`: алерт `HomeserverDown` — это `probe_success == 0` две минуты. Доля времени, когда алерт горит, и есть расход бюджета. Без Grafana хозяин пишет в блокнот время, когда `make smoke` был красным.

## Что делать, когда цель промахнулась

Один раз за месяц из-за перезагрузки — ничего, кроме записи. Повтор в том же месяце — смотреть сон хоста, место на диске и неудачный бэкап. Ранбуки: `docs/runbooks/homeserver-down.md`, `docs/runbooks/disk-full.md`, `docs/runbooks/tailscale-down.md`.
