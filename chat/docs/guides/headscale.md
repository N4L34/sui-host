# Когда смотреть в сторону Headscale

Обычный путь «Свои» — Tailscale. Headscale — отдельное решение, а не запасной режим. Второй полный compose-стек для него в этот репозиторий не добавляйте. Чат остаётся тем же стеком Synapse. Меняется только координация tailnet.

Имеет смысл переходить в двух случаях. В tailnet больше шести пользователей, либо вы не хотите пользоваться координационным сервером Tailscale.

Тарифы и ограничения Tailscale меняются. Перед выбором откройте https://tailscale.com/pricing и сверьте актуальные условия.

Вы теряете две вещи. Автоматические сертификаты HTTPS Tailscale перестают выдаваться, потому что `tailscale serve` и `tailscale cert` завязаны на их координацию. Вход на iPhone перестаёт быть прямым. Человек больше не входит в обычный tailnet и не получает готовое имя `*.ts.net`.

Что придётся сделать самим:

1. Поднимите Headscale отдельным проектом. Не встраивайте его вторым стеком рядом с Synapse.
2. В официальном приложении Tailscale на iPhone укажите свой координационный сервер. Ставьте то же приложение Tailscale, не самодельный клиент.
3. Принесите свой домен и сертификаты либо установите свой CA на каждый телефон. Element X должен доверять сертификату. Публичный порт для этого не открывайте. Если сертификат выдаёт публичный центр, подтверждайте домен через DNS, а не через входящий HTTP.
4. Новое имя сервера принимайте только до первой учётной записи. Настоящее `MATRIX_SERVER_NAME` фиксирует первый `make render`. Пример `tailnet-name` штамп не пишет. Другое имя после штампа — это новый сервер, а не настройка.

Пока пользователей не больше шести и координация Tailscale вас устраивает, оставайтесь на Tailscale. Сертификаты HTTPS и вход на iPhone тогда делает Tailscale.
