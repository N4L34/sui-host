# Работа с узлом

Эти заметки описывают общий процесс администрирования self-hosted установки. Перед командами подставьте адрес своего хоста и используйте только доверенную частную сеть. Не храните реальные адреса и доступы в этом репозитории.

## Деплой

`git push` сам по себе не выкладывает файлы. GitHub Actions запускает `scripts/deploy.sh`, который определяет изменённые проекты, синхронизирует управляемые файлы и пересоздаёт только изменившиеся сервисы. Секреты, `.env`, runtime-файлы и состояние на хосте остаются вне репозитория.

Для ручного обслуживания используйте Compose из каталога нужного проекта:

```bash
docker compose ps
docker compose up -d
docker compose stop
```

Чтобы пересоздать один контейнер без соседей:

```bash
docker compose up --no-deps -d <service>
```

Не используйте `docker compose down -v`, `docker volume prune` и `--remove-orphans`, если не намерены удалять данные. Для чата учитывайте, что пересоздание LiveKit прерывает активные звонки.

## Локальная конфигурация

Каждая установка задаёт имя сервера Matrix, адреса и credentials локально. Переносите только безопасные шаблоны `*.env.example`; не копируйте локальный `.env` в git. Proxy URI и токены не помещайте в логи.

Команды, требующие доступа к хосту, выполняйте через его административный канал. Не вставляйте вывод с внутренними адресами или именами учётных записей в публичные issues.
